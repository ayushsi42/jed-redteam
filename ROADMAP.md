# Roadmap — Agent Red-Team

## Current State
- The build pipeline works end-to-end: `src/jed_redteam/attack.py` → `scripts/build_submission.py` → `submission/attack.py` passes `aicomp validate`, runs under `aicomp test`/`aicomp evaluate`, and has a working notebook build (`submission/notebook/`, `scripts/build_notebook.py`).
- `pytest tests/ -q` passes (6/6) — structural smoke tests plus a few targeted regression guards (keyword-gate safety, pad-message/deterministic-agent keyword compatibility).
- **Strategy change (post-Phase-1): confused-deputy via `email.send` is now the primary strategy** — see README.md "Current Status" for the full reasoning. A stricter guardrail (one that checks every argument and tracks provenance more persistently, not just one argument over a short window) closes off exfiltration/untrusted-to-action chains that score fine against a lenient reference guardrail, while a clean one-hop `email.send` with a fresh recipient per candidate survives and is a pure throughput game. `run()` now builds a time-budget-scaled pool (up to 4000, ~1 per 2s remaining) of keyword-clean, recipient-varying confused-deputy arms and runs them before the (now secondary) discovery/file-wash arms.
- Real evaluation results, confused-deputy strategy, against a real LLM-backed agent (gpt-4o-mini, real API calls):
  - 180s budget: **score 0.51** (`findings_count: 22, unique_cells: 7, unique_canonical_cells: 22, score_raw: 102.0`)
  - 600s budget: **score 2.06** (`findings_count: 99, unique_cells: 8, unique_canonical_cells: 99, score_raw: 412.0`)
  - Confirms near-linear scaling with time budget, as the "throughput over cleverness" framing predicted — this is a large improvement over the prior exfiltration-only best of `0.17`.
- Earlier Phase 1 results (file-wash/exfiltration strategy, retained for history — see README.md):
  - Fast local deterministic agent: **0.0 / 0 findings / 0 unique cells** — and this is a *proven*, not just observed, ceiling. Three independent, code-confirmed properties of the reference guardrail + a simple deterministic agent make all four predicates unreachable together for this specific agent: the protected file can never be successfully read/written/deleted through the guardrail regardless of taint state; the guardrail's 5-event taint window always encloses `UNTRUSTED_TO_ACTION`'s 2-event lookback so a dangerous action can never be simultaneously "recent enough" for the predicate and "old enough" to dodge the guardrail; and the deterministic agent's only path to `email.send` requires the exact keywords that also suppress `CONFUSED_DEPUTY` (this is exactly why the confused-deputy-pool strategy also requires an LLM-backed agent). Confirmed via direct instrumentation of the guardrail and the deterministic agent's logic.
  - Real LLM-backed agent (gpt-4o-mini, exfiltration-only): `0.09` (`findings_count: 1, unique_cells: 1, score_raw: 18.0`) and `0.17` (`findings_count: 2, unique_cells: 1, unique_canonical_cells: 2, score_raw: 34.0`), via the file-wash/taint-aging mechanism hitting a planted multi-hop injection chain.
- `docs/guardrail_analysis.md`'s reverse-engineering is directly implemented in `run()`'s secondary arms, and additionally *extended* by the guardrail-unreachability analysis above.

## Phase 1 — Done
1. ~~Implement fixture discovery instead of static generic prompts.~~ **Done.** `_Discovery` calls `web.search`/`web.open`/`email.read` via `env.interact()`, parses real JSON results and embedded `tool.name(id="...")` references in fetched content to follow multi-hop chains, and ranks discovered content by an injection-strength heuristic (`_bait_score`).
2. ~~Deliberately script the file-wash / taint-aging bypass chain.~~ **Done.** `_run_wash_arm` builds exactly `web/email fetch → 5x benign local fs.read → keyword-clean final action`, confirmed end-to-end against gpt-4o-mini (see Current State).
3. ~~Keep the file-read-back step within `UNTRUSTED_TO_ACTION`'s 2-event lookback.~~ **Superseded by a sharper finding, not implemented as originally scoped.** Direct instrumentation of the guardrail shows this specific idea can't work as stated: the guardrail's 5-event taint window is a strict superset of the predicate's 2-event window over the same ordered event list, so *any* dangerous action within the predicate's 2-event range is unconditionally also within the guardrail's 5-event range and gets denied. The file-wash chain still has real value (it reliably produces `EXFILTRATION`, confirmed against gpt-4o-mini), just not via `UNTRUSTED_TO_ACTION` specifically — see README.md for the full reasoning. `UNTRUSTED_TO_ACTION` remains genuinely open (not scored in any run so far).
4. ~~Control the last user message as a keyword lever, not narrative content.~~ **Done.** `_safe_message` guarantees every action-triggering message is free of `run`/`execute`/`send`/`email`/`upload`/`save`/`write`, with a unit test guarding the property.
5. ~~Add a domain/path diversification strategy.~~ **Done.** `_build_bait_arms` ranks discovered bait by "domain not yet tried" before score, spreading the attempt queue across distinct `http.post`-bucketable domains.
6. ~~Replace `random.choice` with a per-action productivity tracker.~~ **Done, but redesigned rather than a live bandit.** Every backend this harness supports is effectively deterministic given identical input (the deterministic agent's keyword parser; the LLM-backed agent fixes `temperature=0`), so a live bandit re-sampling the same (template, wording) pair would just repeat an already-known outcome forever — confirmed empirically as the actual reason an earlier version of this algorithm burned an entire local test budget on ~100 duplicate no-op attempts. `run()` instead builds a finite, priority-ordered queue of distinct arms up front and consumes each exactly once, dropping a bait item's remaining variants once its tool-call shape converges to an already-seen cell signature.

## Phase 2 — Medium-term (partially done)
1. ~~Add a Go-Explore-style archive keyed on cell signature.~~ **Done, in a lighter form than originally scoped.** Rather than storing an unbounded archive of `(snapshot, cell_signature, score_hint)` tuples, `run()` snapshots only the one expensive-to-reach "prefix" state per bait item (fetch + 5-turn taint pad) and reuses it across that bait's final-message variants, and tracks only small cell-signature hash sets/counters (not full snapshots) to prune exhausted bait — memory stays flat regardless of run length.
2. **Systematic coverage across all 4 predicate categories with tracked per-category hit rates — `CONFUSED_DEPUTY` now done at scale; others unchanged.** `CONFUSED_DEPUTY` now has a dedicated, high-volume arm pool (`_build_confused_deputy_arms`, up to 4000 arms) and has scored repeatedly and at scale against gpt-4o-mini (0.51 at 180s budget, 2.06 at 600s budget — see Current State), confirming it as the dominant real finding, not just an open hypothesis. `DESTRUCTIVE_WRITE` remains provably unreachable against the reference guardrail for *any* agent (its keyword block fires on the literal substring naming the protected file, which is unavoidably present in any path that resolves to it) — **closed, not open**. `UNTRUSTED_TO_ACTION` remains genuinely open and is now the single most valuable remaining gap, since `EXFILTRATION`'s real-world value is now in doubt (see Current State) and `CONFUSED_DEPUTY` is largely solved.
3. ~~Replay-safety hardening.~~ **Done.** Every arm attempt in the main loop is wrapped in `try`/`except`, and a fixed deadline-safety margin is preserved.
4. **Tune against the deterministic agent, then validate against additional LLM backends — partially done.** Tuned and validated against both the fast deterministic agent (proven-ceiling 0.0, see Current State) and a real LLM backend (gpt-4o-mini, real non-zero scores). Open-weight local model backends require local model weights not available in this environment — **still open**.
5. **Verify the encoded-exfiltration path end-to-end — still open.** The sentinel-value path (simpler, and now confirmed working end-to-end against gpt-4o-mini) was prioritized over building a dedicated base64/hex-encoding chain template, since the secret-matcher's decode pass was already established as sound by static analysis. A chain that deliberately induces an agent to base64/hex-encode a *real* protected-file read before posting is moot given the guardrail unconditionally blocks reading that file at all (see Current State) — so this item is now understood to be about encoding a payload that reaches the secret matcher via the sentinel value or some other in-trace-read value, not the literal protected secret. Not attempted.

## Phase 3 — Stretch (unchanged, still open)
1. **A learned/adaptive search policy** — now more naturally framed as learning *which discovered bait/domain is worth an arm* given a fixed per-arm outcome (rather than a live bandit re-sampling identical prompts, which Phase 1 item 6 established is wasted effort against these deterministic-given-input agent backends) — e.g. a lightweight contextual policy over (fixture-source, domain, chain-template) triples using cumulative new-cell yield as a training signal across many runs/seeds.
2. **A documented write-up comparing found exploit classes to the four predicate categories** — the README now documents this at a summary level (which categories are provably unreachable vs. genuinely open vs. confirmed working, and against which agent); a fuller write-up with guardrail-block-reason breakdowns per category is still open.
3. **Extend chain templates beyond the current injection patterns** — e.g. multi-hop laundering through more than one intermediate file/tool-call, or combining two predicate triggers in a single chain. Still open.
4. **A minimal automated regression harness** that runs `aicomp evaluate --agent deterministic` after each strategy change and diffs `unique_cells`/`score` against the last recorded baseline. Given the deterministic ceiling is now proven to be 0.0 regardless of strategy quality, this would need to assert "still 0, and still exhausts its arm queue in well under budget without exceptions" rather than a `unique_cells` diff — still open, and lower priority than adding gpt-4o-mini-backed regression coverage would be.
